## How I work

I care about the shape of systems. Small modules over monoliths. Composition over inheritance. Data-driven configuration over hardcoded logic. Explicit over implicit. Every subsystem with a single job and a documented contract.

I also care about the design that isn't code — the decisions, the trade-offs, the reasons a thing is built one way and not another. My projects tend to accumulate long documentation before they accumulate features.

I'm currently open to software engineering roles where I can work on systems that need genuine thought put into their architecture, not just shipped features.
